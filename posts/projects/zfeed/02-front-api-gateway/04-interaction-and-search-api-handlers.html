本文说明 front-api 网关中社交互动和搜索处理器的实现。这些处理器作为路由与校验层，通过协调 interaction-rpc 和 search-rpc 服务，把复杂领域逻辑封装成简单的 HTTP 端点。

互动 API 处理器 ​

互动子系统覆盖点赞、收藏、关注和楼中楼评论。大多数互动端点都要求通过 UserLoginStatusAuthMiddleware 完成认证。app/front/doc/interaction/interaction.api#169

Scene 抽象 ​

互动请求使用 Scene 参数（例如 "content"、"comment"）将动作路由到正确的领域上下文。app/front/doc/interaction/interaction.api#9 front-api 会先把这些字符串解析为内部枚举值，再传给 RPC 服务。app/front/internal/logic/interaction/likelogic.go#42-45

实现模式：点赞与收藏 ​

点赞和收藏操作遵循统一模式：

  1. 身份提取：从请求上下文获取 userID。app/front/internal/logic/interaction/likelogic.go#37-40
  2. Scene 校验：将字符串 scene 转换为类型化的 RPC scene。app/front/internal/logic/interaction/likelogic.go#42-45
  3. RPC 委托：调用对应的 LikeRpc 或 FavoriteRpc 方法。app/front/internal/logic/interaction/likelogic.go#47-51

楼中楼评论系统 ​

评论系统支持嵌套回复（parent/root 层级）。front-api 通过同一个 Comment handler 同时处理根评论创建和回复创建。app/front/doc/interaction/interaction.api#199-200

数据流：创建评论

  1. 校验：front-api 校验内容长度（最多 255 个 rune）和必填 ID。app/front/doc/interaction/interaction.api#60-65
  2. 楼层解析：interaction-rpc 服务解析 parent_id 和 root_id，确保评论层级有效。app/rpc/interaction/internal/logic/comment/commentlogic.go#154-196
  3. 事务写入：评论被创建，同时根评论的回复数会在同一个 MySQL 事务中递增。app/rpc/interaction/internal/logic/comment/commentlogic.go#66-98
  4. 缓存失效：创建后，系统会让相关 Redis key 失效，包括内容评论列表和特定评论串。app/rpc/interaction/internal/logic/comment/commentlogic.go#112-152

评论缓存架构采用两层 Redis 缓存策略：

  • 索引缓存：使用 ZSet 存储评论 ID，并按 score 排序（通常是时间戳或 ID）。app/rpc/interaction/internal/logic/comment/cache.go#23-48
  • 对象缓存：将单条评论详情以 JSON 字符串形式存储，并设置特定 TTL。app/rpc/interaction/internal/logic/comment/cache.go#93-114

搜索 API 处理器 ​

搜索处理器为用户发现和内容发现提供统一入口。它们会把 HTTP 查询参数转换为 search-rpc 请求，并支持多种排序模式，以及通过快照实现的稳定分页。

搜索请求处理 ​

front-api 会执行基础清洗，例如裁剪空白字符，并限制最大分页大小（默认 20）。app/front/internal/logic/search/searchuserslogic.go#16-48

关键能力：

  • 搜索模式：支持 relevance、latest 或 hybrid 排序。app/front/internal/logic/search/searchlogic_test.go#79-80
  • 查看者上下文：如果用户已登录，会将其 viewerID 传给 RPC，用于补全结果状态（例如 IsFollowing）。app/front/internal/logic/search/searchuserslogic.go#55-75
  • 稳定分页：使用 SnapshotId 和 PageToken，确保底层索引变化时，用户不会看到重复结果或跳过结果。app/front/internal/logic/search/searchcontentslogic.go#62-70

搜索数据流 ​

搜索流程连接了 front-api 类型和 search-rpc protobuf 定义。

内容搜索与用户搜索 ​

  • 内容搜索：返回包括 AuthorName、CoverUrl 和 PublishedAt 在内的元数据。app/front/internal/logic/search/searchcontentslogic.go#85-94
  • 用户搜索：包含 IsFollowing 布尔值，该值由 search-rpc 根据 viewerID 和搜索结果之间的关系检查后补全。app/front/internal/logic/search/searchuserslogic.go#87-93
