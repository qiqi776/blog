认证与会话管理 ​

本文说明 zfeed 系统中的用户认证与会话管理实现。整体架构依赖 Bearer token 流程、Redis 会话存储，以及用于保证会话校验和 TTL（Time-To-Live）续期原子性的 Lua 脚本。

会话生命周期概览 ​

用户通过 user-rpc 服务成功登录或注册后，会创建会话。会话创建后，请求在进入下游业务逻辑之前，会先由 front-api 网关中的自定义中间件完成校验。

会话存储结构 ​

会话以双 key 映射形式存储在 Redis 中，同时支持 token 到用户的查找，以及用户到 token 的管理（例如单设备登录或全局登出）。

Key 模式用途值
user:session:{token}校验指定会话 tokenuserId
user:session:user:{userId}将用户映射到当前活跃 tokentoken

来源：app/front/internal/middleware/sessionauth.go#20-21

认证流程 ​

系统使用标准的 Authorization: Bearer <token> 请求头。front-api 网关主要通过两个中间件处理认证：UserLoginStatusAuthMiddleware 和 OptionalLoginMiddleware。

Token 提取 ​

middleware 中的 extractToken 函数同时处理标准 Bearer 请求头和原始 token 字符串，以保持向后兼容。

来源：app/front/internal/middleware/sessionauth.go#34-50

校验与原子续期 ​

为了减少 Redis 往返次数并避免竞态条件，会话校验和 TTL 延长通过 Lua 脚本（verify_and_renew_session.lua）一次性完成。

  1. 检查 token：脚本取出给定 token 关联的 userId。
  2. 校验一致性：检查 user:session:user:{userId} key 是否仍然指向当前 token，确保该会话没有被新登录顶替。
  3. 续期逻辑：如果剩余 TTL 小于特定阈值（由 renewRatio 定义），则两个 key 都会被延长到完整的 defaultSessionTTL。

会话续期参数 ​

  • 默认 TTL：7 天（7 * 24 * time.Hour）。
  • 续期比例：1/3。当会话剩余生命周期小于总 TTL 的 1/3 时触发续期（7 天会话约为 2.3 天）。

来源：app/front/internal/middleware/sessionauth.go#23-25 app/front/internal/middleware/sessionauth.go#52-92 app/front/internal/middleware/verify_and_renew_session.lua#1-21

组件逻辑

会话校验逻辑详解 ​

verifyAndRenewSession 函数是校验逻辑的核心。它会基于配置的 SessionTTL 计算续期阈值。

go
// From app/front/internal/middleware/sessionauth.go
threshold := int(float64(ttlSeconds) * renewRatio)
tokenKey := redisTokenKeyPrefix + ":" + token
resp, err := rds.EvalCtx(ctx, VerifyAndRenewSessionScript, []string{tokenKey}, token, redisUserKeyPrefix, ttlSeconds, threshold)

Lua 脚本确保只有 token 到用户、用户到 token 两个映射保持同步时，会话才被视为有效：

  1. userId = GET user:session:{token}
  2. storedToken = GET user:session:user:{userId}
  3. if storedToken != token then return ""

这可以防止“幽灵会话”：旧 token 仍然存在于 Redis 中，但实际上已被同一用户的新登录会话替换。

来源：app/front/internal/middleware/sessionauth.go#61-67 app/front/internal/middleware/verify_and_renew_session.lua#3-12

错误处理 ​

认证错误使用 pkg/errorx 包，确保整个 API 返回一致的 HTTP 状态码。

  • 缺少 token：返回 errorx.NewUnauthorized("用户未登录")，映射到 HTTP 401。
  • token 无效或过期：返回 errorx.NewUnauthorized("用户未登录")。
  • 上下文缺少 UserID：如果业务逻辑需要用户 ID，但中间件未提供，则返回 errorx.NewUnauthorized("用户未登录")。
