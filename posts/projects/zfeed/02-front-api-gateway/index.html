Front-API 网关 ​

front-api 服务是 zfeed 生态中所有客户端流量的统一入口。它是一个基于 go-zero 框架构建的 HTTP 网关，负责请求路由、协议转换（HTTP 到 gRPC）、认证，以及从多个下游微服务聚合数据。

网关角色与架构 ​

网关作为门面层存在，对客户端屏蔽微服务拓扑的复杂性。它通过 ServiceContext 初始化并维护到各主要 RPC 服务的 gRPC 客户端连接。app/front/internal/svc/servicecontext.go#25-39

核心职责：

  • 请求路由：根据 API 定义将 HTTP 请求分发到对应的 logic handler。
  • RPC 聚合：编排对 UserRpc、ContentRpc、CountRpc 等服务的调用，构建复杂响应。
  • 中间件执行：在进入业务逻辑之前执行安全策略和会话管理。
  • 错误映射：通过全局错误处理器，将内部 gRPC/业务错误转换为标准 HTTP 状态码。app/front/front.go#31-33

服务上下文与依赖 ​

ServiceContext app/front/internal/svc/servicecontext.go#25-39 是网关的依赖注入容器。它保存 logic 层需要的 gRPC 客户端和共享基础设施句柄。

依赖代码实体作用
用户服务UserRpc认证、资料和用户管理。
内容服务ContentRpc文章/视频生命周期与元数据。
Feed 服务FeedRpc获取推荐 Feed 和关注 Feed。
互动服务LikeRpc、CommentRpc 等社交动作，例如点赞、评论、关注。
搜索服务SearchRpc面向用户和内容的全文搜索。
缓存Redis会话存储和网关级共享缓存。

中间件与安全 ​

网关通过 rest.Middleware 实现两种主要认证模式。app/front/internal/svc/servicecontext.go#37-38

  1. 严格认证（UserLoginStatusAuthMiddleware）：写操作（发布、点赞等）必须经过该认证。它会提取 Bearer token，基于 Redis 校验 token，并把 userID 注入请求上下文。app/front/internal/middleware/userloginstatusauthmiddleware.go#29-47
  2. 可选认证（OptionalLoginMiddleware）：用于读操作（Feed、搜索等）。它会尝试识别用户，以便提供个性化状态（例如 IsLiked），但在没有 token 时也允许匿名访问。

会话生命周期和基于 Lua 的校验细节请参阅认证与会话管理。

API 表面与子系统 ​

API 按功能域拆分，每个功能域由对应的 logic 分组处理：

  • 用户管理：注册、登录和个人资料操作。详情请参阅用户 API 处理器。
  • 内容与 Feed：发布文章/视频，并消费多种 Feed 类型（推荐、关注、用户）。详情请参阅内容与 Feed API 处理器。
  • 互动与搜索：社交信号（点赞、评论）和全文搜索能力。详情请参阅互动与搜索 API 处理器。
