本术语表定义 zfeed 生态中使用的代码库专属术语、架构模式和领域概念。它是面向新工程师的技术参考，用于理解自然语言概念如何映射到具体代码实体。

核心领域术语 ​

内容层级（Content Hierarchy） ​

系统使用“基础表 + 扩展表”模式管理不同媒体类型。

  • Content（基础实体）：表示帖子的通用实体。它保存 visibility、status、hot_score 等元数据。
  • Article/Video（扩展实体）：某一内容类型的专属数据。文章包含标题和描述；视频包含 URL 和封面图。
  • 来源：app/rpc/search/internal/logic/searchlogic_test.go#35-72 app/rpc/interaction/internal/testutil/mysqltest/mysqltest.go#181-183

Scene ​

“Scene” 是用于区分互动发生位置的枚举，例如点赞、评论或收藏发生在哪类目标上。这允许同一套 RPC 逻辑处理不同目标类型，例如点赞文章与点赞评论。

  • 实现：在 protobuf 中定义为 interaction.Scene。
  • 来源：app/rpc/interaction/internal/repositories/like_repository.go#19-22 app/rpc/interaction/internal/logic/like/likelogic_test.go#160

ViewerState ​

ViewerState 是内容详情获取期间使用的一种模式，会根据请求用户与内容之间的关系补充数据，例如 IsLiked、IsFollowing。

  • 来源：app/rpc/content/internal/logic/content/getcontentdetaillogic.go#1-10（通过逻辑流引用）。

技术模式 ​

Transactional Outbox ​

interaction-rpc 服务使用的一种可靠性模式。事件不会直接发布到 Kafka，而是和业务状态变更放在同一个事务中写入 MySQL 表（zfeed_like_event_outbox）。随后由独立 relay 进程轮询该表并推送到 Kafka。

  • 实现：zfeed_like_event_outbox 表。
  • 来源：app/rpc/interaction/internal/testutil/mysqltest/mysqltest.go#76 app/rpc/interaction/internal/testutil/mysqltest/mysqltest.go#146-162

基于 Cursor 的分页（Cursor-based Pagination） ​

内容列表和搜索结果的主要分页方式。它使用一个 ID，通常是 ContentID 或 UserID，作为指向上一页最后一项的指针，从而在数据更新期间保持结果稳定。

  • 来源：app/rpc/search/internal/logic/searchcontentslogic.go#131-134 app/rpc/search/internal/logic/searchuserslogic.go#141-144

Snapshot 分页（Snapshot Pagination） ​

search-rpc 中的一种高级分页模式，会把整个结果集作为“snapshot”缓存在 Redis 中，以便在底层数据变化时仍能为深度分页提供稳定、一致的排序。

  • 实现：searchContentsWithSnapshot 和 loadSearchSnapshot。
  • 来源：app/rpc/search/internal/logic/searchcontentslogic.go#54-59 app/rpc/search/internal/logic/searchcontentslogic.go#159-221

搜索与缓存 ​

查询归一化（Query Normalization） ​

查询归一化是对搜索查询进行清理、分词和哈希的过程，用于提升缓存命中率并避免重复处理。

  • 实现：l.svcCtx.NormalizeQuery(in.GetQuery())。
  • 来源：app/rpc/search/internal/logic/searchcontentslogic.go#36-39 app/rpc/search/internal/logic/searchuserslogic.go#39-42

缓存层级（Cache Tiers） ​

搜索服务使用两个特定缓存层：

  1. Query Cache：缓存某个搜索关键词对应的结果 ID。
  2. Doc Cache：缓存实体（User/Content）的完整摘要，避免补全阶段访问数据库。
  • 来源：app/rpc/search/internal/config/config.go#19-21 app/rpc/search/internal/config/config_env_test.go#23-25
