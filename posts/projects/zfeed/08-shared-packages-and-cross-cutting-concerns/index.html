zfeed 代码库依赖位于 pkg/ 和 orm/ 的一组共享包，以保证各微服务之间的一致性。这些包负责标准化 gRPC 通信、错误转换、环境管理，以及手机号归一化、热度排行公式等与具体领域弱相关的通用工具。

共享包的架构角色 ​

共享包提供了让独立服务能够稳定通信、行为可预测的“胶水层”。通过集中处理拦截器、日志和错误映射逻辑，系统得以维持统一的可观测性与可靠性轮廓。

gRPC 拦截器与错误处理 ​

grpcx 包为服务端和客户端实现了一套稳健的中间件链。它处理分布式追踪所需的请求 ID 传播，使用 logx 进行结构化日志记录，并通过 panic 恢复避免服务崩溃。

其中的关键组件是 ErrorUnaryServerInterceptor，它负责衔接内部业务逻辑与 gRPC 协议。它会自动把 errorx.BizError 类型转换为标准化的 gRPC 状态码。在 front-api 侧，errorx.ResponseFromError 会完成最后一步映射，将错误转换为面向客户端的 HTTP 状态码。

详情请参见 gRPC 拦截器与错误处理。

ORM、环境与工具 ​

系统的基础设施交互通过 orm 和 envx 包进行标准化。这些包确保数据库连接使用一致的设置初始化，例如慢查询日志，同时保证环境变量能在本地、Docker 或 CI 等不同执行上下文中正确加载。

pkg/ 目录还包含一些专用逻辑：

  • mobilex：提供 Normalize 和 IsValid 函数，用来处理多种国际和中国大陆手机号格式 pkg/mobilex/mobile.go#5-20
  • hotrank：实现基于时间衰减的评分算法，由 content-rpc 用于生成推荐 Feed pkg/hotrank/formula_bench_test.go#11-19
  • xxljob：分布式任务调度集成。

详情请参见 ORM、环境加载与工具包。
