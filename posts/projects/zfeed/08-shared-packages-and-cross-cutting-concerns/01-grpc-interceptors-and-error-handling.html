gRPC 拦截器与错误处理 ​

相关源文件
  • pkg/grpcx/interceptors.go
  • pkg/grpcx/interceptors_test.go

zfeed 系统在 grpcx 包中使用集中式 gRPC 管理层，以保证请求可观测性、跨服务可追踪性和稳健的错误转换保持一致。这套基础设施覆盖一次 gRPC 调用的完整生命周期，从 request ID 生成，到结构化日志记录，再到最终错误映射。

gRPC 拦截器流水线 ​

系统同时实现了客户端和服务端拦截器，为所有微服务提供统一的执行环境。

服务端拦截器 ​

InstallServerInterceptors 函数 pkg/grpcx/interceptors.go#46-53 会注册一条拦截器链，执行顺序如下：

  1. RequestIDServerInterceptor：提取或生成唯一的 x-request-id pkg/grpcx/interceptors.go#108-126
  2. StructuredLoggingServerInterceptor：记录请求完成情况，包括 gRPC 状态码和执行耗时 pkg/grpcx/interceptors.go#128-145
  3. RecoveryUnaryServerInterceptor：捕获 handler 内部的 panic，并将其转换为 gRPC internal 错误 pkg/grpcx/interceptors.go#164-181
  4. ErrorUnaryServerInterceptor：将内部 BizError 类型转换为标准 gRPC 状态码 pkg/grpcx/interceptors.go#147-162

客户端拦截器 ​

客户端使用 ClientInterceptorOption pkg/grpcx/interceptors.go#39-44，其中串联了：

  1. RequestIDClientInterceptor：把上下文中的当前 request_id 传播到出站 gRPC metadata pkg/grpcx/interceptors.go#72-84
  2. StructuredLoggingClientInterceptor：记录出站调用，包括目标 peer 地址和返回状态 pkg/grpcx/interceptors.go#86-106

Request ID 传播 ​

系统通过 x-request-id metadata key 传递 request_id 来维持可追踪性 pkg/grpcx/interceptors.go#21

  • 生成：如果服务端收到的请求没有 request ID，RequestIDServerInterceptor 会生成新的 UUID pkg/grpcx/interceptors.go#117-120
  • 注入：ID 通过 withRPCLoggingContext 加入上下文，并作为 logx.LogField 附加进去 pkg/grpcx/interceptors.go#123
  • 传播：当服务发起下游调用时，RequestIDClientInterceptor 会从上下文读取 ID，并重新放入出站 gRPC metadata pkg/grpcx/interceptors.go#79-81

来源：pkg/grpcx/interceptors.go#21-27 pkg/grpcx/interceptors.go#108-126 pkg/grpcx/interceptors.go#72-84

错误处理与转换 ​

系统区分内部业务逻辑错误（BizError）和传输层 gRPC 错误。ErrorUnaryServerInterceptor 作为边界，确保内部错误详情在离开服务前被正确映射到 gRPC code。

BizError 到 gRPC 的映射 ​

ErrorUnaryServerInterceptor 使用 errors.As 检测 *errorx.BizError pkg/grpcx/interceptors.go#153-156。随后它调用错误对象上的 GRPCStatus() 方法，获取对应的 google.golang.org/grpc/status 表示。

业务错误状态gRPC Code说明
BizError（通用）codes.Internal未特殊处理的业务错误的默认映射。
errorx.NewNotFoundcodes.NotFound用于资源不存在的场景，例如用户或内容不存在 pkg/grpcx/interceptors_test.go#135-152
Panic 恢复codes.InternalRecoveryUnaryServerInterceptor 返回 errorx.DefaultErrorMessage pkg/grpcx/interceptors.go#176

Panic 恢复 ​

RecoveryUnaryServerInterceptor 使用 defer 中的 recover() pkg/grpcx/interceptors.go#165-166。捕获 panic 后，它会使用 debug.Stack() 记录完整堆栈跟踪 pkg/grpcx/interceptors.go#175，并向客户端返回干净的 gRPC Internal 错误，从而避免服务进程崩溃，也避免敏感堆栈信息泄露。

来源：pkg/grpcx/interceptors.go#147-181 pkg/grpcx/interceptors_test.go#134-172

结构化日志 ​

日志由 StructuredLoggingServerInterceptor pkg/grpcx/interceptors.go#128 和 StructuredLoggingClientInterceptor pkg/grpcx/interceptors.go#86 执行。

日志字段 ​

拦截器会为每条日志补充特定字段，方便在日志聚合系统中检索：

  • request_id：请求链的唯一 ID pkg/grpcx/interceptors.go#224-226
  • rpc_system：固定为 grpc pkg/grpcx/interceptors.go#228
  • rpc_kind：取值为 server 或 client pkg/grpcx/interceptors.go#229
  • grpc_service：gRPC 服务名称，例如 zfeed.search.SearchService pkg/grpcx/interceptors.go#234
  • grpc_method：具体 RPC 方法，例如 SearchUsers pkg/grpcx/interceptors.go#235
  • grpc_code：gRPC 状态码的字符串表示，例如 OK、NotFound pkg/grpcx/interceptors.go#133
  • duration：请求处理耗时 pkg/grpcx/interceptors.go#135
