本页为 zfeed 微服务使用的 MySQL 数据库 schema 提供完整技术参考。系统使用名为 zfeed 的单一逻辑数据库来存储所有持久化领域数据，包括用户、内容、社交互动和计数；任务调度则使用独立的 xxl_job 数据库 scripts/sql/bootstrap/init.sql#1-10

数据库初始化与 Bootstrap ​

数据库环境通过 bootstrap 脚本初始化，该脚本会创建所需数据库、用户和权限 scripts/sql/bootstrap/init.sql#1-8。随后它执行一系列 SQL 文件来创建表并应用迁移 scripts/sql/bootstrap/init.sql#12-25

核心领域 Schema ​

用户管理（zfeed_user） ​

zfeed_user 表存储用户资料信息和认证凭据。它使用生成列（active_mobile、active_email）只对未删除用户施加唯一约束，使手机号可以在账号删除后被再次使用 scripts/sql/zfeed_user.sql#1-28

  • 关键索引：
  • uk_active_mobile：对活跃手机号施加唯一约束 scripts/sql/zfeed_user.sql#22
  • ft_user_search：在 nickname、bio 和 mobile 上建立全文索引，供 search-rpc 使用 scripts/sql/zfeed_user.sql#27

内容层级 ​

zfeed 使用“基础表 + 扩展表”模式。zfeed_content 保存通用元数据，而类型专属数据位于 zfeed_article 或 zfeed_video 中 scripts/sql/zfeed_content.sql#1-17 scripts/sql/zfeed_article.sql#1-14 scripts/sql/zfeed_video.sql#1-16

表主要用途关键字段
zfeed_content元数据与排序hot_score, visibility, published_at
zfeed_article长文本内容title, content（LONGTEXT）, cover
zfeed_video视频媒体origin_url, duration, transcode_status
  • 排序支持：zfeed_content 包含 idx_hot_score（hot_score、id），用于支持推荐引擎高效检索热门内容 scripts/sql/zfeed_content.sql#23

互动与社交图谱 ​

社交互动通过状态表追踪，这些表支持软删除和用于幂等性的版本控制。

  • zfeed_like 与 zfeed_favorite：使用 scene 和 content_id 区分对文章、视频或评论的点赞/收藏 scripts/sql/zfeed_like.sql#1-19 scripts/sql/zfeed_favorite.sql#1-19
  • zfeed_comment：使用 parent_id（直接父评论）和 root_id（顶层评论）实现线程式评论结构 scripts/sql/zfeed_comment.sql#1-27
  • zfeed_follow：追踪 follower/followee 关系，并对关系对设置唯一约束 scripts/sql/zfeed_follow.sql#1-16

可靠消息与计数器 ​

Transactional Outbox ​

为了保证互动事件投递到 Kafka 时具备 “Exactly-Once” 或 “At-Least-Once” 语义，系统使用 outbox 表。

  • zfeed_like_event_outbox：在与状态变更相同的数据库事务中保存点赞事件。随后由 LikeOutboxRelay 轮询该表 scripts/sql/zfeed_like_event_outbox.sql#1-16

计数系统（zfeed_count_value） ​

count-rpc 服务在该表中管理所有高频计数。它使用 biz_type 和 target_type 判别字段，以统一格式存储点赞数、收藏数、评论数和关注数 scripts/sql/zfeed_count_value.sql#1-15

  • 乐观锁：version 列用于避免并发递增时发生丢失更新 scripts/sql/zfeed_count_value.sql#7

MQ 幂等（zfeed_mq_consume_dedup） ​

count-rpc consumer 使用该表确保经由 Canal 处理的 MySQL binlog 事件不会被重复应用 scripts/sql/zfeed_mq_consume_dedup.sql#1-10

迁移策略 ​

代码库采用幂等迁移模式。它没有使用传统的顺序迁移文件，例如 v1__init.sql、v2__add_col.sql，而是在每个 SQL 文件中使用 IF NOT EXISTS 子句，并通过 MySQL PREPARE/EXECUTE 语句执行动态 DDL 块 scripts/sql/zfeed_article.sql#16-31

示例：生成列迁移 ​
