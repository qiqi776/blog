zfeed 是一个使用 Go、go-zero 微服务框架和 Docker Compose 构建的高性能内容社区系统。README.md#1-7 它实现了一套现代社交媒体架构，覆盖内容发布、多策略 Feed 流、高频计数器和全文搜索。

系统采用微服务拓扑设计，将不同职责拆分到专门的 RPC 服务中，由 API 网关统一协调，并依托 MySQL、Redis、Kafka、Canal 等基础设施组件支撑运行。README.md#21-30

核心能力 ​

  • 用户管理：注册、登录、会话处理和个人资料统计。README.md#34
  • 内容生命周期：支持文章和视频发布，并提供复杂的详情聚合能力。README.md#35
  • Feed 系统：推荐流（热门内容排序）、基于关注关系的收件箱，以及面向用户的个性化 Feed。README.md#36
  • 社交互动：原子化的点赞/取消点赞流程、楼中楼评论，以及收藏/关注系统。README.md#37
  • 搜索与发现：通过 Redis 快照为用户搜索和内容搜索提供稳定分页。README.md#39
  • 可观测性：集成 Prometheus 指标、Jaeger 链路追踪和结构化日志。README.md#40

系统搭建指南请参阅快速开始。

服务拓扑 ​

系统由一个 API 网关（front-api）和六个专门的 RPC 服务组成。这些服务通过 gRPC 通信，并使用 Etcd 进行服务发现。deploy/docker-compose.yml#21-36

服务端口主要职责
front-api5000HTTP 入口、认证中间件、RPC 聚合。README.md#25
user-rpc5003身份认证、会话、个人资料管理。README.md#26
content-rpc5001内容生命周期、Feed 生成、热门排序。README.md#27
interaction-rpc5002点赞、评论、收藏、关注。README.md#28
count-rpc5004高频计数器、基于 Canal 的 CDC。README.md#29
search-rpc5006全文搜索、结果缓存。README.md#30

架构与数据流 ​

zfeed 同时使用同步 gRPC 调用和异步事件驱动模式：前者满足即时数据需求，后者处理计数、搜索索引等衍生影响。

  1. 请求聚合：front-api 充当 Backend-for-Frontend（BFF），聚合多个 RPC 服务的数据。例如，GetContentDetail 会并发调用 user-rpc 获取作者信息、调用 count-rpc 获取统计数据，并调用 interaction-rpc 获取当前浏览者的点赞/关注状态。app/rpc/content/internal/logic/content/getcontentdetaillogic.go#180-212
  2. 事件驱动计数器：当用户点赞一篇内容时，interaction-rpc 会写入 MySQL。Canal 监听 MySQL binlog 并将事件发布到 Kafka，随后 count-rpc 消费这些事件，更新 zfeed_count_value 中的高频计数器。README.md#29 app/rpc/count/internal/model/count_model.go#5-15
  3. 搜索与分页：search-rpc 使用 Redis 快照管理稳定分页，确保新内容持续发布时，用户不会看到重复项或漏掉结果。README.md#30

可观测性栈 ​

系统已接入生产级监控所需的观测能力。app/rpc/search/internal/logic/observability.go#29-71

  • 指标：自定义 Prometheus 直方图和计数器（例如 zfeed_search_request_duration_ms）用于追踪延迟与错误率。app/rpc/search/internal/logic/observability.go#30-37
  • 链路追踪：OpenTelemetry（OTEL）采集器将 trace 转发到 Jaeger，用于可视化跨服务请求链路。deploy/docker-compose.yml#167-190
  • 日志：各服务输出结构化 JSON 日志，并可通过 Filebeat/Logstash 管道进行聚合。deploy/.env#49-50 app/rpc/search/etc/search.yaml#16-31
