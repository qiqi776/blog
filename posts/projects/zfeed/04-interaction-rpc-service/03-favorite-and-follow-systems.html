收藏与关注系统是 interaction-rpc 服务中的核心社交组件。它们处理用户与内容、用户与用户之间的关系，并结合 MySQL 持久化存储、Redis 高速关系查询，以及 Transactional Outbox 模式，将事件可靠投递到 count-rpc、content-rpc 等下游服务。

收藏系统架构 ​

收藏系统允许用户保存文章、视频或评论。它维护双重状态：MySQL 中的主记录，以及 Redis 中用于快速判断“是否收藏”和支持基于 cursor 收藏 Feed 的缓存表示。

数据流：收藏与取消收藏 ​

当用户收藏一条内容时，系统会在数据库中执行幂等 Upsert，并在同一个事务内把事件记录到 zfeed_favorite_event 表。app/rpc/interaction/internal/logic/favorite/favoritelogic.go#61-104

  1. 目标所有者解析：写入前，系统通过 resolveFavoriteTargetOwner 解析内容所有者（文章/视频作者或评论作者）。app/rpc/interaction/internal/logic/favorite/favoritelogic.go#137-158
  2. 事务写入：Favorite 逻辑使用 MySQL 事务，确保收藏记录和 outbox 事件原子创建。app/rpc/interaction/internal/logic/favorite/favoritelogic.go#61-104
  3. 缓存失效：数据库写入成功后，删除关系缓存（fav:rel:{scene}:{user}:{content}），防止读到旧值。app/rpc/interaction/internal/logic/favorite/favoritelogic.go#113-116
  4. Feed 更新：对于文章和视频，系统使用 Lua 脚本 AddUserFavoriteIfExistsScript 更新用户收藏 Feed 的 Redis ZSet；如果该 ZSet 存在，则维护它。app/rpc/interaction/internal/logic/favorite/favoritelogic.go#122-132

关注系统与资料摘要 ​

关注系统管理用户之间的社交图谱。它支持关注、取消关注，以及用于个人资料页的批量查询。

关注/取消关注逻辑 ​

FollowUser 和 UnfollowUser 方法处理用户关系的状态转换。

  • 关注：在 zfeed_follow 中创建或更新一条记录，并设置 Status=1。app/rpc/interaction/internal/model/interaction_model.go#37-52
  • 取消关注：将记录更新为 Status=0。
  • 可靠性：与收藏类似，关注动作会触发事件；这些事件由 count-rpc 用于更新粉丝/关注数，也由 content-rpc 用于管理关注收件箱。app/rpc/interaction/proto/interaction.proto#307-314

批量关注状态与摘要 ​

对于个人资料页和列表视图，服务提供优化后的查询方法：

  • BatchQueryFollowing：一次调用中检查查看者是否关注了一组目标用户。app/rpc/interaction/proto/interaction.proto#260-272
  • GetFollowSummary：返回总量计数（粉丝数/关注数）以及查看者与目标用户之间的具体关系。app/rpc/interaction/proto/interaction.proto#274-283

可靠投递：FavoriteEventOutbox ​

为了确保互动计数最终一致，系统使用 Transactional Outbox。当收藏发生变化时，会向 zfeed_favorite_event 写入一条记录。app/rpc/interaction/internal/model/interaction_model.go#22-35

  1. 事件生成：FavoriteLogic 生成唯一 EventID，例如 favorite_{user}_{content}_{timestamp}。app/rpc/interaction/internal/logic/favorite/favoritelogic.go#96-103
  2. 下游消费：count-rpc 服务通过 Canal（MySQL Binlog）消费这些变化，并将更新应用到 zfeed_count_value 表。app/rpc/count/internal/event/strategy/favorite_strategy.go#25-62
  3. 幂等性：下游消费者使用 zfeed_mq_consume_dedup 表确保每个 EventID 只被处理一次。app/rpc/interaction/internal/repositories/mq_consume_dedup_repository_test.go#18-27

Count-RPC 中的收藏策略 ​

计数服务中的 favoriteStrategy 会从 binlog 中提取更新。它识别操作类型（INSERT/DELETE/UPDATE），并为目标内容的收藏数计算 delta（+1 或 -1）。app/rpc/count/internal/event/strategy/favorite_strategy.go#38-53

操作条件Delta
INSERT状态为活跃+1
DELETE状态为活跃-1
UPDATE状态 0 -> 1+1
UPDATE状态 1 -> 0-1

查询与分页 ​

收藏列表分页 ​

QueryFavoriteList 方法使用基于 FavoriteId（收藏记录主键）的 cursor 分页。app/rpc/interaction/internal/logic/favorite/queryfavoritelistlogic.go#30-75

  • 请求：接收 cursor 和 page_size。app/rpc/interaction/proto/interaction.proto#109-113
  • 仓储：调用 ListContentByUserCursor 获取 pageSize + 1 条记录，用于判断是否还有下一页。app/rpc/interaction/internal/logic/favorite/queryfavoritelistlogic.go#43-48
  • 响应：将当前结果集中最后一项的 ID 作为 next_cursor 返回。app/rpc/interaction/internal/logic/favorite/queryfavoritelistlogic.go#65-74

收藏信息（计数与状态） ​

QueryFavoriteInfo 逻辑首先使用 BuildFavoriteRelKey 构建 key，并在 Redis 中查询“是否收藏”状态。app/rpc/interaction/internal/logic/favorite/queryfavoriteinfologic.go#61-74 如果缓存未命中，则查询数据库并带 TTL 回填缓存。app/rpc/interaction/internal/logic/favorite/queryfavoriteinfologic.go#76-91
