测试与基准测试 ​

本节概述 zfeed 代码库采用的多层测试与基准测试策略。系统的测试层级从隔离的单元逻辑，到全栈端到端（E2E）验证，再到高并发性能测试套件。

测试层级总览 ​

测试策略旨在保证分布式边界上的正确性，尤其关注数据一致性（幂等性）、Cache-Aside 可靠性，以及系统在负载下的性能表现。

1. 单元测试与集成测试 ​

代码库使用专用工具模拟基础设施组件，而无需启动完整 Docker 栈。这使业务逻辑和仓储层可以被快速、隔离地验证。

  • 数据库模拟：仓储层集成测试，例如 LikeRepository，使用本地 MySQL 实例或 SQLite，并由 mysqltest 工具管理 schema 约束和行清理 app/rpc/interaction/internal/testutil/mysqltest/mysqltest.go#29-53
  • 缓存模拟：使用 miniredis 在隔离环境中验证 Redis Lua 脚本和 TTL 逻辑。
  • Consumer 验证：LikeConsumer 等消息逻辑通过在测试数据库上模拟 Kafka payload，验证幂等性与事件合并行为 app/rpc/interaction/internal/mq/consumer/like_consumer_test.go#29-62

实现细节和模式请参见 单元测试与集成测试。

2. 端到端（E2E）测试 ​

E2E 测试运行在真实 Docker Compose 栈上。这类测试验证跨多个微服务和基础设施组件（Canal、Kafka、Redis、MySQL）的“happy path”。

  • 链路验证：TestCountChainE2E 等测试验证一次互动，例如点赞，是否能正确穿过 interaction-rpc outbox、进入 Kafka、经由 count-rpc dispatcher，最终更新 zfeed_count_value 表。
  • 系统状态：验证热门内容快照和可观测性流水线（Prometheus/Jaeger），确保线上操作期间 trace 和 metrics 能正确发出。

3. 性能基准测试 ​

zfeed 包含一套完整基准测试，用于度量系统上限并定位瓶颈。

  • gRPC 基准测试：使用 ghz 直接压测 RPC 服务，例如在 127.0.0.1:5001 上针对 feed-* 使用合成数据集 bench/ghz/README.md#1-25
  • HTTP 负载测试：使用 k6 针对 front-api 网关模拟不同流量模式，包括 smoke、spike 和 soak 测试 bench/k6/config.js#57-70
  • 场景覆盖：覆盖读密集（Feed 推荐）、写密集（社交互动）和搜索密集工作负载，并定义 SLO 阈值 bench/k6/config.js#7-18

运行基准测试和 E2E 套件的详情请参见 端到端与性能测试。
