本页描述用于大规模验证系统完整性和性能的测试策略。zfeed 测试套件不止包含单元测试和集成测试，还包括针对真实 Docker 栈的端到端（E2E）场景、通过 ghz 进行的 gRPC 基准测试，以及使用 k6 进行的 HTTP 负载测试。

端到端（E2E）测试 ​

E2E 测试验证多个微服务和基础设施组件（Kafka、Canal、Redis、MySQL）之间的交互。这些测试通常针对完整 Docker Compose 环境执行。

关键 E2E 场景 ​

  • Count Chain E2E（TestCountChainE2E）：验证异步计数流水线。它触发一次互动，例如点赞，验证事件被写入 Transactional Outbox、转发到 Kafka、由 count-rpc 通过 Canal CDC 消费，并最终反映到 count_value 表和 Redis 缓存中。
  • Recommend Hot Snapshot E2E（TestRecommendHotSnapshotE2E）：验证推荐 Feed 的稳定性。它确保用户请求 RecommendFeed 时，系统能正确使用基于 Lua 的 snapshot 逻辑 app/rpc/content/internal/common/utils/lua/query_hot_feed_zset.lua#1-107，在并发排行更新期间仍提供一致的热门内容视图。
  • Observability E2E（TestObservabilityE2E）：验证请求能跨服务边界传播 x-request-id，并且 Prometheus 能正确抓取指标。

性能与负载测试 ​

性能测试分为微基准测试（Go testing.B）、gRPC 服务基准测试（ghz）和系统级 HTTP 负载测试（k6）。

Go 微基准测试 ​

内部逻辑性能通过 Go 内置基准测试工具度量。这些测试关注缓存 key 生成、序列化、查询归一化等高频操作。

函数用途文件
BenchmarkDefaultNormalizerNormalize度量搜索查询清洗和分词速度。app/rpc/search/internal/querynorm/normalizer_bench_test.go#7-23
BenchmarkBuildCountValueCacheKey基准测试 count 服务的 Redis key 构造。app/rpc/count/internal/logic/count_cache_bench_test.go#15-20
BenchmarkParseHotFeedLuaResult度量复杂 Feed Lua 脚本返回结果的解析效率。app/rpc/content/internal/logic/feed/feed_bench_test.go#39-53
BenchmarkContentItemsToFollowItems基准测试将内容项转换为 Feed 项的补全流水线。app/rpc/content/internal/logic/feed/feed_bench_test.go#16-37

gRPC 基准测试（ghz） ​

ghz 工具用于对单个 RPC 方法进行基准测试。配置文件位于 bench/ghz/ 中，定义并发级别、请求 payload 和目标方法。

  • Feed Recommend：以并发 20、总计 1000 个请求测试 content.FeedService.RecommendFeed bench/ghz/feed-recommend.json#1-17
  • Like Hot Content：测试 interaction.LikeService.Like 的写路径 bench/ghz/like-hot-content.json#1-19

HTTP 负载测试（k6） ​

k6 用于模拟真实用户行为的高层场景。这些测试以 front-api 网关为目标。

  • 场景：
  • Hot Content：高并发访问推荐 Feed 和热门内容详情 bench/k6/scenarios/hot-content.js
  • Search：使用 search_terms.csv 中的各种词语模拟用户搜索内容和资料 bench/k6/scenarios/search.js
  • Write-Heavy：模拟快速发布和社交互动。

基准测试数据管理 ​

为确保测试可复现且安全，bench/data/ 目录包含用于初始化环境的合成数据。

数据布局与规则 ​

所有基准测试数据都必须使用 bench_ 前缀，以区别于生产数据或标准开发数据 bench/data/README.md#19-25

  • users.csv：包含合成用户资料，例如 bench_user_10001 bench/data/small/users.csv#1-8
  • content_ids.csv：用于互动测试的预定义内容 bench/data/small/content_ids.csv#1-6
  • search_terms.csv：常见和边界搜索查询 bench/data/small/search_terms.csv#1-6
  • tokens.json：session token 的占位文件。真实 token 应该在测试运行的 setup 阶段生成，而不是提交到仓库 bench/data/small/tokens.json#1-4

执行与归档 ​

基准测试通过 scripts/bench/run.sh 脚本执行，该脚本编排环境准备、数据初始化和工具运行。

  1. 环境准备：确保 Docker 栈已运行且健康。
  2. 数据初始化：将 bench/data/small/*.csv 加载到 MySQL 数据库中。
  3. 执行：运行 k6、ghz 或 go test -bench。
  4. 归档：结果（延迟分位数、吞吐量、错误率）会保存到 bench/results/，用于历史对比 bench/results/README.md
