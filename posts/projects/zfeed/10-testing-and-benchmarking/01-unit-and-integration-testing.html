zfeed 的测试策略强调使用内存基础设施和专用工具实现高保真隔离，以保证数据库 schema 约束、缓存正确性和消息处理幂等性。单元测试主要验证 logic 包中的业务逻辑，集成测试则覆盖仓储层、缓存和数据库层之间的交互。

测试基础设施与工具 ​

为了在不依赖真实 Docker 栈的情况下提供接近真实的测试环境，zfeed 使用了多种基础设施内存替代方案。

内存基础设施 Provider ​

  • Redis：使用 miniredis 模拟，它提供真实 Redis 兼容的 TCP server。测试通过 gzredis.MustNewRedis 将其集成进来 app/rpc/search/internal/logic/searchlogic_test.go#87-95
  • MySQL：使用 SQLite 内存模式和 cache=shared 模拟。为了弥合 SQLite 与 MySQL 语法差异，测试使用 GORM 的 AutoMigrate 根据实体定义生成 schema app/rpc/search/internal/logic/searchlogic_test.go#74-85
  • gRPC 依赖：下游 RPC 服务会替换为 Stub 实现，例如 stubSearchFollowService，以便针对特定测试用例注入自定义行为 app/rpc/search/internal/logic/searchlogic_test.go#126-152

mysqltest 工具 ​

对于需要真实 MySQL 特性的服务，例如 ON DUPLICATE KEY UPDATE 或特定索引行为，会使用 mysqltest 工具。该工具管理到专用测试数据库的连接，通常位于 33306 端口，并提供辅助函数来维护 schema 状态。

函数职责
Open()初始化到测试 MySQL 实例的 GORM 连接 app/rpc/interaction/internal/testutil/mysqltest/mysqltest.go#29-53
EnsureLikeTables()为 zfeed_like、zfeed_mq_consume_dedup 和 outbox 表执行 DDL app/rpc/interaction/internal/testutil/mysqltest/mysqltest.go#68-174
CleanupLikeRowsByRange()删除特定 ID 范围内的数据，以保证测试隔离 app/rpc/interaction/internal/testutil/mysqltest/mysqltest.go#253-270
CleanupDedupRows()清理 MQ consumer 测试中的幂等 token app/rpc/interaction/internal/testutil/mysqltest/mysqltest.go#272-282

来源：app/rpc/search/internal/logic/searchlogic_test.go#74-95 app/rpc/interaction/internal/testutil/mysqltest/mysqltest.go#1-174

仓储层与幂等性测试 ​

interaction-rpc 服务高度依赖 Transactional Outbox 和幂等 Upsert 模式。测试这些能力需要验证特定数据库状态转换。

Like Repository 集成 ​

LikeRepository.Upsert 实现使用复杂的 ON DUPLICATE KEY UPDATE 查询，并通过 GREATEST(last_event_ts, VALUES(last_event_ts)) 处理乱序事件 app/rpc/interaction/internal/repositories/like_repository.go#46-79

Like Upsert 的测试用例：

  • Newer Wins：时间戳更高的事件会覆盖现有状态 app/rpc/interaction/internal/repositories/like_repository_test.go#27-72
  • Older Ignored：时间戳更低的事件不会改变记录，即使 status 不同 app/rpc/interaction/internal/repositories/like_repository_test.go#74-122

Consumer 幂等性 ​

LikeConsumer 测试验证针对重复消息的双层保护：

  1. 应用层：检查 zfeed_mq_consume_dedup 表 app/rpc/interaction/internal/mq/consumer/like_consumer_test.go#29-62
  2. 数据库层：Upsert 逻辑处理过期时间戳 app/rpc/interaction/internal/mq/consumer/like_consumer_test.go#112-161

缓存隔离与并发模式 ​

Redis Lua 脚本测试 ​

RecommendFeedLogic 使用复杂 Lua 脚本（QueryHotFeedZSetScript）在 Redis 中执行原子分页和 snapshot 选择 app/rpc/content/internal/logic/feed/recommendfeedlogic.go#133-145。单元测试会重点覆盖这些结果的解析器，确保缓存未命中、空 snapshot、无效 cursor 等边界情况都能被处理。

删除时的缓存清理 ​

DeleteContentLogic 包含复杂的 cleanupIndexes 流程，会使多个 Redis key 失效，包括 Follow Inbox、Favorite Feed 和 Hot Feed app/rpc/content/internal/logic/content/deletecontentlogic.go#108-118。集成测试验证内容在 MySQL 中被软删除后，对应成员会从 Redis ZSet 中移除 app/rpc/content/internal/logic/content/deletecontentlogic.go#188-192
