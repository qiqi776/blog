user-rpc 服务是 zfeed 生态中用户身份和资料管理的中心权威。它处理注册、基于密码的认证、会话签发和细粒度资料管理等敏感操作。它是 zfeed_user 表的事实来源，并为 content-rpc 等其他服务提供批量查询能力，用于补全用户元数据。

服务架构 ​

该服务遵循清晰的架构模式，将 gRPC 传输层、业务逻辑和数据持久化分离。

数据流：注册与登录 ​

用户注册或登录时，服务会执行校验，调用 UserRepository 进行持久化，并通过共享工具在 Redis 中管理会话状态。

标题：用户认证与注册流程

来源：app/rpc/user/internal/logic/registerlogic.go#38-102 app/rpc/user/internal/logic/loginlogic.go#34-72 app/rpc/user/internal/repositories/user_repository.go#95-117

核心组件 ​

1. 手机号校验与归一化 ​

服务使用 mobilex 包保证手机号处理一致，支持标准 11 位中国大陆号码、86 前缀和 E.164 格式。

  • 归一化：将多种格式（例如 +86138...）转换为标准 11 位字符串，用于数据库索引。pkg/mobilex/mobile.go#5-15
  • 候选查找：按手机号搜索用户时，仓储会生成多个候选值（原始值、带 86、带 +86），确保历史格式或不同输入格式仍能找到正确记录。pkg/mobilex/mobile.go#22-41

2. 用户仓储（UserRepository） ​

仓储使用 GORM 抽象所有与 zfeed_user 表的交互。它负责在数据库 model.ZfeedUser 和业务层 do.UserDO 之间映射。

方法说明实现细节
GetByMobile按手机号查找活跃用户。遍历 mobilex.LookupCandidates 生成的候选值。app/rpc/user/internal/repositories/user_repository.go#37-53
GetByID获取单个用户资料。按 id 和 is_deleted = 0 过滤。app/rpc/user/internal/repositories/user_repository.go#55-72
BatchGetByIDs高效获取多个用户资料。使用 WHERE id IN ?，为 Feed 补全提供高性能读取。app/rpc/user/internal/repositories/user_repository.go#74-93
UpdateProfile局部更新用户字段。使用 UserProfilePatch 和 GORM Updates(map[string]any) 执行字段级更新。app/rpc/user/internal/repositories/user_repository.go#119-169

来源：app/rpc/user/internal/repositories/user_repository.go#15-21

3. 会话管理 ​

会话不存储在 MySQL 中，而是由 Redis 管理，以支持 front-api 中间件中的高并发校验。

  • Token 生成：使用加密安全随机 token。app/rpc/user/internal/logic/registerlogic.go#92
  • TTL：会话时长可通过 GetSessionTTL 配置。app/rpc/user/internal/logic/registerlogic.go#91
  • 存储：SaveSession 工具将 token -> userID 映射持久化到 Redis。app/rpc/user/internal/logic/registerlogic.go#93

资料初始化逻辑 ​

注册过程中，如果可选字段缺失，服务会应用默认值，确保每个用户都有完整资料。

  • 昵称：未提供时默认使用用户手机号。app/rpc/user/internal/logic/registerlogic.go#113-119
  • 邮箱：如果留空，会生成内部占位邮箱，例如 register-138...@zfeed.local。app/rpc/user/internal/logic/registerlogic.go#121-140
  • 生日：将时间戳截断到当天开始时间（00:00:00），以保证隐私和一致性。app/rpc/user/internal/logic/registerlogic.go#142-152

实现细节：Logic 类 ​

服务实现被拆分为多个专门的 logic 类，每个类处理一个特定 gRPC 方法。

批量用户查询 ​

BatchGetUser 逻辑由 content-rpc 和 interaction-rpc 使用，允许系统在一次往返中解析一组内容项所需的用户头像和昵称。这可以在 RPC 层避免 “N+1” 查询问题。
